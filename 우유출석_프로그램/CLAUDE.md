# 우유 꿀꺽 출석부 — 작업 메모

초등학교 5학년 담임교사가 쓰는 교실용 웹앱.
학생이 **우유갑에 쓴 자기 이름 손글씨**를 보여주면 티처블 머신 이미지 모델이
누구인지 알아맞혀서 우유 출석을 찍어준다. 대학 수업(그래픽스개론) 과제물도 겸한다.

- 배포: GitHub Pages — https://m2026-create.github.io/milka/
- 저장소: https://github.com/m2026-create/milka

## 기본 원칙 (지켜 주세요)

- **사진은 절대 외부로 보내지 않는다.** 판별은 전부 브라우저 안에서(tfjs). 서버 업로드 금지.
- **학생 실명은 저장소에 올리지 않는다.** `js/config.js` 의 roster 는 테스트용 가명만 둔다.
  실제 명단은 선생님 화면(⚙️)에서 입력해 localStorage 에만 저장된다.
  `우유출석_*.json`(내보낸 기록, 실명 포함)은 `.gitignore` 로 막아뒀다.
- 설명·주석·UI 문구는 모두 **한국어**. 초등학생이 읽는 화면이라 쉬운 말로, 실패해도 기죽지 않는 문구로.
- 교사가 직접 고칠 값은 `js/config.js` 한 곳에 모아두고 한국어 주석을 붙인다.

## 실행 / 확인 방법

카메라(`getUserMedia`)와 모델 로딩은 **https 또는 localhost 에서만** 동작한다.
`file://` 로 열면 카메라가 안 켜진다. 반드시 로컬 서버로 띄워서 확인할 것.

```
node tools/devserver.cjs 8777     # → http://localhost:8777
```

클로드코드에서는 `.claude/launch.json` 의 **`milk`** 설정으로 preview_start 하면 된다.

개발 PC에는 카메라가 없다. 그래서 동작 확인은 `getUserMedia` / `enumerateDevices` /
`model.predict` 를 브라우저 콘솔에서 가짜로 바꿔치기(stub)해서 한다. 예:

```js
model = { predict: async () => [
  {className:'Sia', probability:0.95},
  {className:'Minha', probability:0.03},
  {className:'Jaha', probability:0.02},
]};
```

## 파일 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 본 앱. 화면 7개를 `.screen` 섹션으로 두고 JS가 `active` 클래스를 옮겨 전환 |
| `js/config.js` | **교사가 고치는 설정** — 명단, 모델 위치, 인식 기준, 쿠폰 규칙, 칭찬/재시도 문구 |
| `js/app.js` | 전부. 카메라, 판별, 출석 반영, 메인 현황판, 선생님 화면 |
| `js/streak.js` | 연속 일수 계산 (주말·쉬는 날 제외) |
| `js/store.js` | localStorage 저장 (`milk-attendance-v1`) |
| `css/style.css` | 전체 스타일. 손글씨 느낌 폰트(Jua/Gaegu), 파스텔, 큰 버튼 |
| `eval.html` | **모델 평가 페이지.** 사진 여러 장 → 혼동행렬·클래스별 정분류율·틀린 사진 모음·CSV. 파일명 밑줄 앞부분을 정답 클래스로 읽는다 (`can_01.jpg` → `can`) |
| `collect.html` | **학습 사진 모으기.** 학생이 직접 찍어 IndexedDB 에 쌓고, 교사가 폴더/ZIP 으로 내려받아 티처블 머신 학습에 쓴다. 누가 며칠 올렸는지 표로 보여준다 |
| `model/` | 티처블 머신 Tensorflow.js 내보내기 3종 (`model.json` · `weights.bin` · `metadata.json`) |
| `tools/devserver.cjs` | 로컬 확인용 정적 서버 |
| `tools/augment_images.py` | 사진 증강 (⚠️ 아래 주의) |

## 출석 흐름 (2026-11 재설계됨)

예전: 이름 카드를 먼저 누르고 → 사진 찍어 "이 사람 맞아?" 확인 (2지선다)
지금: **출석하기 → 촬영 또는 사진 올리기 → "누구야?" 판별 → 그 학생으로 자동 인정** (N지선다)

판별은 `js/app.js` 의 `identify(canvas)` 한 곳에서만 한다. 통과 조건 두 개:

1. `confidenceMin` — 1위 확률이 이 값 이상 (선생님 화면 **% 슬라이더**, 40~99)
2. `marginMin` — 1위와 2위 확률의 차이가 이 값 이상 (두 학생 사이 혼동 방지, 0이면 끔)

실패 사유를 `reason` 으로 구분한다: `notstudent`(1위가 명단에 없음) / `lowconf` / `unsure`.

사진 여러 장을 한 번에 올리면 `handleFiles()` 가 장마다 판별·출석 반영하고
`screen-batch` 에 **인증됨 / 이미 먹음 / 모르겠어요** 요약을 띄운다.

메인 화면은 현황판: 오늘 반 진행 막대, 🏆 이달의 우유 친구 시상대(2-1-3 순서로 그림),
순위 목록(🔥연속 · 놓친 날 · 🎟️쿠폰). **통계는 모두 이번 달 기준**이다
(`thisMonth()` / `monthCount()` / `monthMissed()`). 달이 바뀌면 다 0에서 시작 —
순위 때문에 아이들이 기죽지 않게 한 의도적 선택이다.

`놓친 날 = 이달 1일~오늘 사이 학교 가는 날 수 − 먹은 날 수`

## 알려진 함정

- **모델이 지금 테스트용이다.** 클래스가 `Sia / Minha / Jaha` 3개뿐이고
  **'우유갑아님' 클래스가 없다.** 그래서 아무 사진이나 찍어도 셋 중 하나로 통과할 수 있다.
  실제 사용 전에 반드시 '우유갑아님'(배경·손·책상 등) 클래스를 넣어 다시 학습해야 한다.
- **N지선다로 바꾸면서 정확도가 떨어질 수 있다.** 제안서의 교육적 질문이 바로 이 비교라서,
  `eval.html` 로 두 방식 혼동행렬을 비교하면 그대로 과제 자료가 된다.
- `tools/augment_images.py` 는 `raw/` 전체를 증강한다. **증강 전에 train/dev/test 를 먼저 나눠야 한다.**
  안 나누면 같은 사진의 변형이 학습·평가 양쪽에 들어가 성능이 부풀려진다(데이터 누출).
- CSV 는 엑셀에서 한글이 깨지지 않게 맨 앞에 BOM(`﻿`)을 붙인다. 지우지 말 것.
- 촬영/업로드 이미지는 **가운데 정사각형으로 자른 뒤** 리사이즈한다(`toSquare`).
  학습 때 기하와 맞춰야 하므로 비율을 바꾸지 말 것. 판별 224, 수집 320.
- 티처블 머신 ☰ 메뉴의 `.tm` 파일은 `modelURL` 에 쓸 수 없다. **Tensorflow.js 내보내기**를 받아야 한다.
- 선생님 화면 비밀번호 기본값 `1234`.
